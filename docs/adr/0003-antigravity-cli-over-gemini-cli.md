# Google terminal agent: Antigravity CLI (`agy`), not Gemini CLI

Adding a Google coding agent alongside Claude Code and Codex meant choosing between two real tools. **Gemini CLI** (`@google/gemini-cli`, npm, binary `gemini`) is mature (v0.44.x) but Google is transitioning individual users off it onto **Antigravity CLI** (binary `agy`), a self-updating native Go binary that reuses the same `~/.gemini/` config tree. We chose `agy` despite it being brand-new (v1.0.3 at adoption) — installing onto a sunset tool to gain short-term stability is a bad trade when the successor is already shipping and config-compatible. Auth is OAuth "Login with Google" against a **Google AI Pro** subscription, done once per machine; no API key, no 1Password secret — same manual-login posture as Claude Code and Codex.

Three mechanics differ from how Codex/Claude are wired, each forced by what `agy` actually is (verified against the v1.0.3 binary, not the docs, which were wrong on two of these):

- **Excluded from `dotup`.** `agy` self-updates in the background, so adding it to the hourly `dotup` updater would be redundant and could race the binary's own updater. Install is a one-time `run_once_after_03c` script (official `install.sh` on mac + Linux → `~/.local/bin/agy`, already on PATH via `dot_zshenv.tmpl`), guarded on `command -v agy`.
- **Instructions live in `AGENTS.md`, not `GEMINI.md`.** The binary references `AGENTS.md`; the `~/.gemini/GEMINI.md` that the old gemini-cli created is ignored by `agy`. So global instructions deploy to `~/.gemini/AGENTS.md` (same content as Codex's `AGENTS.md`). *Unverified:* that `agy` loads a **global** `AGENTS.md` at `~/.gemini/` rather than only a project-root one — confirm post-auth with a marker + `agy -p`, and drop the file if it turns out to be dead config.
- **Auto-approve is a launch flag, not a config field.** Unlike Codex (`approval_policy`/`sandbox_mode` in `config.toml`) and Claude (`defaultMode` in `settings.json`), `agy` has no persistent settings file — the only lever is `--dangerously-skip-permissions`. So the "trusted dev box" posture is a gated shell alias (`alias agy='agy --dangerously-skip-permissions'`) in `dot_aliases.tmpl`, applied on `linux-dev`/`mac-dev`/`mac-personal`. This is interactive-only by nature (aliases don't affect scripts), which is the desired blast radius. **Caveat:** `linux-dev` runs as root; whether `agy` refuses `--dangerously-skip-permissions` under root the way Claude Code does (see ADR 0002) is untested — if it does, the `IS_SANDBOX=1` escape hatch already set for that box may or may not apply.

**Revisit if** `agy` v1.x stabilizes a real settings file (move auto-approve out of the alias into config, matching Codex), if the global-`AGENTS.md` assumption proves false (drop the instructions file), or if Google reverses the Gemini-CLI sunset (no action needed — `agy` still works).
