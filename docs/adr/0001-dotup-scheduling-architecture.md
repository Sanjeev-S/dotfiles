# dotup scheduling: hourly fire with a 24h success gate, terminal banner on failure

`dotup` (script that runs `chezmoi update --force`, then Claude self-update, Matt Pocock skills sync, then `npm install -g @openai/codex`) runs on a schedule across three machine types — `mac-personal` (intermittently awake laptop), `mac-dev` and `linux-dev` (always-on remotes). Picking a fixed daily time (e.g., `0 9 * * *`) loses runs on the laptop whenever it's asleep at that hour and forces timezone alignment across hosts. Instead the scheduler fires hourly on every machine and the script itself no-ops if `~/.local/state/dotup/last-success` is younger than 24h. Sleeping ≠ failure (the script simply doesn't execute), so this gives the laptop a self-healing catch-up the first hour after wake without spamming runs on the always-on boxes. `dotup --force` bypasses the gate for manual runs.

Failure surfaces as a banner in `dot_zshrc.tmpl` driven by `~/.local/state/dotup/last-failure`, **not** via the existing ntfy infrastructure. ntfy.sh's default 12h retention is shorter than the laptop's worst-case sleep window, so a proactive push notification can be silently lost; a file-backed banner that fires every new shell session can't be missed and needs no network at notification time. Continue-on-error semantics inside `dotup` mean the banner lists which specific steps failed (e.g., `chezmoi, codex`). The next fully-successful run deletes `last-failure` and clears the banner.

Per-platform scheduler: `launchd` LaunchAgent with `StartInterval = 3600` on the Macs (reuses the `com.sanjeev.ntfy-subscriber` precedent), `systemd --user` service+timer on Linux. systemd-user over cron was picked for chezmoi-managed unit files (mirrors the plist model) and structured `journalctl` logs; the one-time cost is `sudo loginctl enable-linger $USER` if the timer needs to survive full logouts, which bootstrap detects-and-instructs rather than auto-sudoing.
