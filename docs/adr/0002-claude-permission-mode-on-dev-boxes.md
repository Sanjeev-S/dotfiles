# Claude Code permission mode on dev boxes: `auto`, not `bypassPermissions`

`dot_claude/settings.json.tmpl` sets `permissions.defaultMode` for the always-on remotes (`linux-dev`, `mac-dev`) so Claude Code runs unattended without permission prompts. The obvious choice was `bypassPermissions` ("everything, no checks"), but the `linux-dev` box runs Claude as **root**, and Claude Code refuses to start `bypassPermissions` / `--dangerously-skip-permissions` under root or sudo (`"cannot be used with root/sudo privileges for security reasons"`). Setting `defaultMode: bypassPermissions` in settings does not help: the mode can only be *entered* via the enabling flag, which root blocks — so root silently falls back to prompting. This is why a benign `tail -f /tmp/…log | grep` was still prompting even though the allow-list looked permissive.

Three ways out were considered: (a) `IS_SANDBOX=1` (an undocumented env var that makes Claude treat the box as a sandbox and skips the root check, re-enabling `bypassPermissions`); (b) run Claude as a non-root user (everything on this host lives under `/root` — a large rework); (c) `defaultMode: "auto"`, which has **no root restriction** because it is not `bypassPermissions`. Auto mode runs every shell/network action past a server-side classifier that auto-approves benign local operations (the `/tmp` tail sails through silently) and only interrupts for genuinely dangerous actions — `curl|bash`, data exfiltration, prod deploys, mass deletion, force-push.

Chose **(c) auto**. It fixes the prompt-fatigue symptom with a one-line config change, needs no undocumented flags, and keeps a safety backstop on a network-connected box — unlike bypass, which offers zero protection against prompt injection. The trade-offs accepted: auto is *not* literally "everything" (it can still stop on the dangerous set and falls back to prompting after repeated blocks), it drops blanket `Bash(*)` allow rules on entry, adds a classifier round-trip + token cost per shell/network action, and requires Claude Code ≥ 2.1.83 on Opus/Sonnet 4.6+ via the Anthropic API. `defaultMode: auto` is only honored in `~/.claude/settings.json` (ignored in project-level settings) — which is exactly where these dotfiles deploy it.

**Revisit if auto prompts too often.** If the classifier blocks routine work and the fallback prompting becomes annoying, the next step is `IS_SANDBOX=1` in the `linux-dev` block of `dot_zshenv.tmpl` plus `defaultMode: bypassPermissions` — total bypass, accepting the loss of injection protection on a box treated as disposable. `mac-dev` (non-root) can take `bypassPermissions` directly without the env hack if ever desired.

## Addendum (2026-07-12): revisit taken — both dev boxes now use `bypassPermissions`

Auto's classifier friction wasn't worth the backstop, and `IS_SANDBOX=1` had already crept into `dot_zshenv.tmpl` without this ADR being amended. Now the config commits fully to the fallback described above: `defaultMode: bypassPermissions` for `linux-dev` **and** `mac-dev` (one consistent posture; mac-dev needs no env hack), with `IS_SANDBOX=1` kept on `linux-dev` to clear the root check. Accepted trade-off: no injection protection on the dev boxes. Still to verify on the root box: that bypass actually engages rather than silently falling back to prompting (`/permissions` inside a session shows the active mode).
