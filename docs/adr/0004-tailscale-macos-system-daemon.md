# Tailscale on the Mac mini: open-source system daemon, not the GUI app

The Mac mini (`mac-dev`) is an always-on dev box that must be reachable over the tailnet from boot, unattended. The hand-installed GUI Tailscale app broke this in practice: it runs inside a logged-in user session, so any reboot that lands on the login screen silently takes the machine off the tailnet — the observed "shows disconnected, can't ssh" failure. Tailscale's official guidance still prefers the GUI app on macOS for its tighter OS network-extension and DNS integration, which is what makes this choice worth recording.

Three ways out were considered: (a) keep the GUI app and enable auto-login so a session always exists — smallest change, but it adds an unmanaged System Settings step, leaves an interactive session permanently open on a network-reachable box, and still dies to session quirks (fast user switching, logout); (b) the open-source `tailscaled` from the brew formula, registered once via `sudo tailscaled install-system-daemon` — a LaunchDaemon that connects at boot with no user session, CLI-only, with MagicDNS handled by the daemon's own DNS configuration; (c) leave Tailscale unmanaged and fix it by hand each time, which is how it broke.

Chose **(b) system daemon**. It fixes the actual failure mode (connectivity must not depend on a login session), is expressible as idempotent script lines in this repo, and keeps the auth boundary intact — `tailscale up` remains the explicit manual step, consistent with the policy that no tailnet credential lives in the repo. Trade-offs accepted: no menu-bar UI on the mini (CLI only), upgrades are two-step — `install-system-daemon` copies the binary to `/usr/local/bin/tailscaled` and the LaunchDaemon runs that copy, so after `brew upgrade tailscale` the daemon must be re-registered with `sudo tailscaled install-system-daemon`, and this is not Tailscale's recommended macOS variant, so niche GUI-app features (Taildrop, exit-node picker UI) are absent or CLI-only. The Air keeps the GUI app — it is an interactive laptop, which is exactly the machine the GUI app is designed for.

**Revisit if** the official macOS app gains a supported headless/system mode, or if the open-source daemon develops DNS/MagicDNS problems on macOS updates — the fallback is (a) with auto-login, accepting its session fragility.
